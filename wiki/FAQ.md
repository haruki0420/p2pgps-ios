# FAQ

## そもそも何をするアプリ？

iPhone（または Android）の GPS 位置を BLE で iPad に送り、iPad 上で「その位置にいる」ように位置情報を反映します。位置情報ゲームの検証、位置依存アプリのデモ・テスト、遠隔地の再現などに使えます。

## クラウドに位置情報は送られますか？

いいえ。通信は BLE の P2P のみで、座標は端末外（クラウド）に送りません。ログもメモリ内のみで、座標は設定した桁数に丸めます。

## Mac は必要ですか？

ビルドには不要です。Linux / WSL2 + [xtool](https://github.com/xtool-org/xtool) でビルドし、SideStore 等でサイドロードします。ただし、位置注入のための pairing file の取得など初期セットアップには PC が必要な場合があります。

## Android からも送れますか？

はい。プロトコル v1 は共通で、`p2pgps-android` が Sender として実装しています。iPad 側の受信・注入はこのアプリが担当します。

## 同時に複数の iPhone から受け取れますか？

v1 は **1 対 1** です。iPad は同時に 1 台の送信側と接続します。複数接続は v2 以降の予定です。

## 位置注入に必要なものは？

1. Developer Mode
2. LocalDevVPN（無料）
3. pairing file（この iPad 自身のもの）
4. Developer Disk Image（アプリがダウンロード）

詳細は [docs/receiver-setup.md](https://github.com/haruki0420/p2pgps-ios/blob/main/docs/receiver-setup.md)。

## 注入は既定で OFF ですか？

はい。仕様 §8 のとおり既定 OFF で、ユーザーが画面で ON にしたときだけ注入します。注入中は画面上部に常時バナー（送信元・座標・停止）を表示します。

## 第三者が偽の位置を送れるのでは？

v1 は認証・暗号化を行いません（BLE の Just Works 相当）。近距離にいる第三者が偽の位置を送れるため、次の対策をしています。

- 自動接続はユーザーが明示的に許可した送信元のみ
- 注入は既定 OFF・明示操作
- 注入中は常時バナー表示

v2 でアプリ層の HMAC / ペアリングコードを追加する余地を残しています（Control の `AUTH 0x10` を予約）。

## バックグラウンドで動きますか？

- Sender: 送信中は `bluetooth-peripheral` + `location` のバックグラウンドモードで、画面を消しても送信を継続します。位置情報は「常に許可」を推奨。停止中は位置セッションも止まります。
- Receiver: 受信自体は `bluetooth-central` で起床できますが、注入の 5 秒再送はタイマーなので、iOS に suspend されると止まります。そのため**注入 ON の間は `BackgroundKeepAlive`（低精度の位置情報セッション）でアプリを維持**します。注入 ON のまま画面を離れても維持され、停止するのは注入 OFF か設定でバックグラウンド維持を OFF にしたときです。バッテリーとのトレードオフがあるため、必要に応じて設定で無効化してください。

## 位置が元に戻ってしまいます

送信側がバックグラウンドで停止している可能性があります。iOS のバックグラウンド制約で、送信側アプリが完全に停止すると位置が更新されません。送信側を前面に戻すか、位置情報の「常に許可」を確認してください。受信側のライブバナーが消えていれば注入は停止しています。受信側で注入を続けたまま画面を消す場合は、設定の「バックグラウンド維持（受信側）」が ON か確認してください。

## アプリを再起動したら位置が元に戻りません

アプリを再起動すると、前回のプロセスが残したデバイス側のシミュレーションセッションはアプリのハンドルが無いため停止できません。iPad を再起動するか、注入を ON → OFF すると解消します。アプリ再起動直後は注入 OFF の状態から始まります。

## 実機でしか動かないのですか？

この開発環境には Xcode / Swift / 実機がなく、**実機・シミュレータでの動作検証は未実施**です。CI はコンパイルとリンクのみを検証します。BLE と位置注入は実機での確認が必要です。

## ライセンスは？

本リポジトリは **AGPL-3.0** です。位置注入エンジンが StikDebug / TLocation（AGPL-3.0）の派生であるためです。帰属は [NOTICE](https://github.com/haruki0420/p2pgps-ios/blob/main/NOTICE) を参照してください。プロトコル仕様と Python 実装（`p2pgps-protocol`）は MIT です。

## 不具合を見つけたら？

「診断」画面のログを共有し、再現手順・端末・iOS バージョンとともに GitHub の Issue で報告してください。座標はログ設定の桁数に丸められています。

## 更新を自動化できますか？

SideStore / AltStore の**ソース**に対応しています。このリポジトリは public なので、SideStore の Sources に次を追加すると、新しいリリースが自動で一覧に表示されます。

```
https://raw.githubusercontent.com/haruki0420/p2pgps-ios/main/source/apps.json
```

ソースの更新は CI（Release IPA の成功後）で自動化されています。アプリの更新インストール自体は SideStore 上でタップが必要です。詳細は [docs/source.md](https://github.com/haruki0420/p2pgps-ios/blob/main/docs/source.md) を参照してください。
